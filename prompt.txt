# Live Streaming Architecture & Implementation Guide

This document provides the complete architecture and step-by-step implementation guide to build your web-based live streaming feature. 

Because your main codebase is actively serving production traffic through a Cloudflare tunnel, **you should build this inside a completely separate, standalone folder** (e.g., `live-stream-prototype`) to avoid breaking your live site.

---

## 1. Core Architecture

To support 30 to 250 concurrent students where the teacher broadcasts video/audio and students can open their mics, you must use a **Selective Forwarding Unit (SFU)**. 

We will use **Mediasoup**, an open-source C++ SFU that integrates directly into Node.js. 

### The Network Flow
1. **The Teacher** (Producer) uploads **one** video and audio stream to the Mediasoup Router on your backend.
2. **The Students** (Consumers) download the teacher's video and audio stream from the Mediasoup Router.
3. If a student unmutes to ask a question, they upload their audio to the Router, and the Router forwards it to everyone else.
4. **Recording**: The Teacher's browser records the final mixed audio/video using `MediaRecorder` and sends it to the backend in chunks to be automatically uploaded to Hetzner.

**`server.js` Architecture:**
```javascript
const express = require('express');
const http = require('http');
const { Server } = require('socket.io');
const mediasoup = require('mediasoup');

const app = express();
const server = http.createServer(app);
const io = new Server(server, { cors: { origin: '*' } });

let worker;
let router;

// 1. Initialize Mediasoup Worker
async function startMediasoup() {
  worker = await mediasoup.createWorker();
  router = await worker.createRouter({
    mediaCodecs: [
      { kind: 'audio', mimeType: 'audio/opus', clockRate: 48000, channels: 2 },
      { kind: 'video', mimeType: 'video/VP8', clockRate: 90000, parameters: {} }
    ]
  });
  console.log('Mediasoup Router initialized');
}

startMediasoup();

// 2. Socket.io Signaling
io.on('connection', (socket) => {
  console.log('User connected:', socket.id);

  // Step 1: Send RTP Capabilities to the client so they know what codecs are supported
  socket.on('getRouterRtpCapabilities', (callback) => {
    callback(router.rtpCapabilities);
  });

  // Step 2: Create a WebRTC Transport (Upload or Download pipeline)
  socket.on('createWebRtcTransport', async (callback) => {
    const transport = await router.createWebRtcTransport({
      listenIps: [{ ip: '127.0.0.1', announcedIp: null }], // Use your machine's IP if testing across network
      enableUdp: true,
      enableTcp: true,
      preferUdp: true,
    });
    
    // Store transport in a map tied to the socket.id here...

    callback({
      id: transport.id,
      iceParameters: transport.iceParameters,
      iceCandidates: transport.iceCandidates,
      dtlsParameters: transport.dtlsParameters,
    });
  });

  // Step 3: Handle Producer (Teacher sending video)
  socket.on('produce', async ({ transportId, kind, rtpParameters }, callback) => {
    // Find the transport, call transport.produce()
    // Broadcast to other sockets that a new producer exists
    callback({ id: producer.id });
  });

  // Step 4: Handle Consumer (Student receiving video)
  socket.on('consume', async ({ rtpCapabilities, producerId }, callback) => {
    // Find the student's receive transport, call transport.consume()
    callback({ id: consumer.id, producerId, kind: consumer.kind, rtpParameters: consumer.rtpParameters });
  });
});

server.listen(4000, () => console.log('Test SFU running on port 4000'));
```

### B. Test Frontend Setup
Open a terminal in the `frontend` folder and run:
```bash
npx create-react-app . --template typescript
```

**`App.tsx` Architecture:**
```tsx
import React, { useEffect, useRef, useState } from 'react';
import { io } from 'socket.io-client';
import * as mediasoupClient from 'mediasoup-client';

const socket = io('http://localhost:4000');

export default function App() {
  const videoRef = useRef<HTMLVideoElement>(null);
  const [device, setDevice] = useState<mediasoupClient.Device | null>(null);

  useEffect(() => {
    socket.on('connect', async () => {
      // 1. Get Router Capabilities
      socket.emit('getRouterRtpCapabilities', async (routerRtpCapabilities) => {
        // 2. Initialize Mediasoup Device
        const newDevice = new mediasoupClient.Device();
        await newDevice.load({ routerRtpCapabilities });
        setDevice(newDevice);
      });
    });
  }, []);

  const startBroadcasting = async () => {
    if (!device) return;

    // 1. Get Camera/Mic
    const stream = await navigator.mediaDevices.getUserMedia({ video: true, audio: true });
    if (videoRef.current) videoRef.current.srcObject = stream;

    // 2. Ask backend to create a Send Transport
    socket.emit('createWebRtcTransport', async (params) => {
      const sendTransport = device.createSendTransport(params);

      // 3. Connect Transport
      sendTransport.on('connect', ({ dtlsParameters }, callback, errback) => {
        socket.emit('connectTransport', { dtlsParameters }, callback);
      });

      // 4. Produce (Send Media)
      sendTransport.on('produce', async ({ kind, rtpParameters }, callback, errback) => {
        socket.emit('produce', { kind, rtpParameters }, ({ id }) => callback({ id }));
      });

      // 5. Start sending the video and audio tracks
      await sendTransport.produce({ track: stream.getVideoTracks()[0] });
      await sendTransport.produce({ track: stream.getAudioTracks()[0] });
    });
  };

  const startViewing = async () => {
    // Similar flow, but you ask backend to create a Receive Transport
    // Then you call receiveTransport.consume() using the teacher's producerId
    // And attach the resulting track to your videoRef
  };

  return (
    <div>
      <h1>Live Stream Prototype</h1>
      <button onClick={startBroadcasting}>Start Broadcasting (Teacher)</button>
      <button onClick={startViewing}>Watch Stream (Student)</button>
      <video ref={videoRef} autoPlay playsInline muted />
    </div>
  );
}
```

## 3. The Auto-Recording Architecture (The "VOD" Solution)

Instead of the server trying to record the stream (which requires heavy CPU and complex FFmpeg RTP pulling), we will use **Browser-Side Recording** on the Teacher's machine.

1. Once the teacher starts the broadcast and the `MediaStream` is active, initialize a `MediaRecorder` in the React frontend. We will attempt to record directly in `MP4` format for the local backup:

```javascript
const recordedChunks = [];

// Try to use MP4 (H264) if the browser supports it, otherwise fallback to WebM
const mimeType = MediaRecorder.isTypeSupported('video/mp4;codecs=avc1') 
  ? 'video/mp4;codecs=avc1' 
  : 'video/webm;codecs=vp8,opus';

const mediaRecorder = new MediaRecorder(stream, { mimeType });

// Every 5 seconds, send the recording chunk to the server AND save it locally
mediaRecorder.ondataavailable = (event) => {
  if (event.data.size > 0) {
    // 1. Send chunk to backend for auto-upload
    socket.emit('recording-chunk', event.data);
    
    // 2. Keep a copy in the browser's memory for the local backup
    recordedChunks.push(event.data);
  }
};

// When the teacher clicks "End Live"
mediaRecorder.onstop = () => {
  // Automatically trigger a file download on the Teacher's computer
  const isMp4 = mimeType.includes('mp4');
  const extension = isMp4 ? 'mp4' : 'webm';
  const blob = new Blob(recordedChunks, { type: isMp4 ? 'video/mp4' : 'video/webm' });
  
  const url = URL.createObjectURL(blob);
  const a = document.createElement('a');
  a.style.display = 'none';
  a.href = url;
  a.download = `Live-Backup-${new Date().toISOString()}.${extension}`;
  document.body.appendChild(a);
  a.click();
  window.URL.revokeObjectURL(url);
};

mediaRecorder.start(5000); // 5000ms chunks
```

2. On the **Backend**, listen for these chunks and write them to a temporary file:
```javascript
const fs = require('fs');
// We save it temporarily exactly as it arrives
const tempFilePath = './temp-recordings/session_123.tmp';
const writeStream = fs.createWriteStream(tempFilePath);

socket.on('recording-chunk', (chunk) => {
  writeStream.write(chunk);
});

socket.on('end-broadcast', () => {
  writeStream.end();
  
  /* 
    Trigger your EXACT EXISTING FFmpeg Workflow here!
    FFmpeg will read the temporary file and convert it directly to HLS:
    
    ffmpeg -i ./temp-recordings/session_123.tmp -c:v libx264 -c:a aac -f hls index.m3u8
    
    Once the .m3u8 and .ts files are generated, upload them to Hetzner just like you 
    do with your normal pre-recorded courses, then delete the temporary file!
  */
});
```

This perfectly satisfies your requirement to auto-record the live session and upload it to Hetzner without leaving the platform, all while keeping your server CPU usage extremely low.
